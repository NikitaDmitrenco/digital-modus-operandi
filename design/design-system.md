# Design system / DMO

## 1. Палитра

| Token | Hex | Назначение |
|---|---:|---|
| `ink-950` | `#0B0C0B` | Основной фон, hero, footer |
| `ink-900` | `#101310` | Темные секции, карточки |
| `ink-800` | `#171C17` | Поверхность карточек и полей |
| `paper-100` | `#F1F3EA` | Основной off-white текст |
| `paper-300` | `#AEB5A6` | Вторичный текст |
| `paper-500` | `#778172` | Моно-лейблы и технические подписи |
| `lime-400` | `#C7FF45` | Единственный яркий акцент: CTA, статусы, ссылки, hover |
| `moss-700` | `#253326` | Глубокий зелёный в декоративных слоях |
| `light-100` | `#E7E9DF` | Светлые секции процесса и команды |

Лайм используется дозированно. Он не заполняет большие фоны и не участвует в декоративных радугах: это визуальный эквивалент статуса «можно действовать».

## 2. Типографика

| Роль | Шрифт | Размер / интерлиньяж | Трекинг |
|---|---|---|---|
| Display headings | Space Grotesk 500 | `clamp(3.7rem, 8.8vw, 9.5rem)` / `.86` | `-.085em` |
| Hero display | Space Grotesk 500 | до `13.5rem` / `.86` | `-.09em` |
| UI/body | Manrope 400–700 | `12–15px` / `1.45–1.55` | normal |
| Technical labels | DM Mono 400–500 | `9–10px` / normal | `.08–.12em` |

Display-тип используется редко и большими массами; body-тип поддерживает читаемость; mono создаёт инженерный слой интерфейса и маркирует навигацию, номера секций, категории и статусы.

## 3. Сетка и spacing

Базовая сетка — 12 колонок с внешним полем `5.2vw` на desktop и `6vw` на mobile. На крупных экранах вертикальный ритм секций обычно составляет `118–145px`; для внутренних блоков используются ступени `9 / 15 / 20 / 28 / 40 / 55 / 78 / 105px`. Базовый gap между карточками — `8–16px`, между крупными текстовыми колонками — `8–10vw`.

Grid-line слой строится на `rgba(241, 243, 234, .07)` и используется как едва заметная координатная система. Линии не должны конкурировать с текстом.

## 4. Базовые компоненты

### Header

Фиксированный минимальный header: круглый `D`-знак, двухстрочный wordmark, технический статус доступности и компактная кнопка меню. Длинного горизонтального меню нет. При открытии меню появляется полноэкранный overlay с крупными пунктами, stagger-анимацией и `Escape-friendly` визуальным состоянием.

### Buttons

Primary CTA — лаймовый прямоугольник без скругления, off-black текст, стрелка вверх-вправо. Secondary CTA — прозрачный фон, тонкая граница, off-white/grey текст. Hover поднимает кнопку на 3px и усиливает контраст; active уменьшает масштаб до `0.97`.

### Tags and labels

Технические теги — моноширинный upper-case текст в рамке `1px`, без pills и сильного radius. Секционные номера оформляются как `// 01`, service IDs — как `SERVICE_02`.

### Cards

Темные карточки используют `#171C17`, слабую границу и плотный внутренний padding. Hover меняет фон и border, а не добавляет агрессивное свечение. Светлые карточки команды работают как архивные досье: ID, фото-плейсхолдер, role, bio и skills.

### Forms

Поля — без отдельных коробок, только нижняя линия и крупный ввод в Space Grotesk. Техническая подпись находится сверху. Success-state формы явно сообщает, что отправка локальная и относится к прототипу.

### Accordion

FAQ построен на вертикальном списке с border-bottom. Иконка `+` поворачивается на 45 градусов при раскрытии; ответ раскрывается через grid-template rows, а не через резкое изменение высоты.

## 5. Motion

Основной easing — `cubic-bezier(.23, 1, .32, 1)`. Входящие элементы используют `opacity + translateY`, hover — только `transform` и `opacity`, чтобы не провоцировать layout shift. Reveal-блоки получают задержки 90–230ms. Marquee идёт по линейной анимации, orbit-слои вращаются медленно.

Для `prefers-reduced-motion: reduce` отключаются существенные анимации, автоповторы, плавный scroll и transition-delay; скрытые reveal-элементы показываются сразу, поэтому смысл страницы сохраняется без motion.

## 6. Responsive

На ширине около `900px` двухколоночные композиции переходят в вертикальные, сервисы становятся сеткой 2×2, команда — 2×2. На `620px` layout становится одной колонкой, display уменьшается, process превращается в читаемый список, карточки кейсов перестраивают result-блок под основным описанием, а кастомный курсор отключается.
