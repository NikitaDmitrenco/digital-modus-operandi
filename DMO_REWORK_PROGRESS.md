## 4. Открытые вопросы клиенту

### 4.0 Переменные окружения

Аналитику решили пока не подключать (решение №11 в §5). Осталась одна пара —
доставка заявок. Задаётся в Vercel → Project → Settings → Environment
Variables, окружения **Production и Preview**:

| Переменная | Для чего | Где читается |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота, которым отправляется заявка | `api/lead.ts` |
| `TELEGRAM_CHAT_ID` | чат, куда падает заявка | `api/lead.ts` |

Работают **только вместе**: без пары канал считается ненастроенным, функция
отвечает 503, а форма показывает fallback с готовым письмом — заявка не
теряется молча.

**Значения в репозиторий не кладутся.** Токен бота — секрет, он задаётся
только в дашборде Vercel. В коде нет ни `.env` с значениями, ни хардкода;
шаблон с именами переменных (без значений) лежит в `.env.example`.
Отдельно: у токена **не должно быть префикса `VITE_`** — такие переменные
Vite вшивает в публичный бандл.

Необязательные:

| Переменная | Для чего | Что без неё |
|---|---|---|
| `LEAD_WEBHOOK_URL` | альтернатива Telegram: заявка уходит POST-запросом на любой URL (CRM, Make, n8n) | не используется, достаточно пары Telegram |
| `VITE_SITE_URL` | канонический домен для canonical, OG и sitemap | берётся `https://digital-modus-operandi.vercel.app` |

Проверка после деплоя: отправить тестовую заявку через форму — должен
появиться экран «Заявка принята», а не предложение написать письмом.

### 4.10 Шрифты без кириллицы — ЗАКРЫТО 18.09.2026

**Проблема.** Space Grotesk (все крупные заголовки) и DM Mono (технические
подписи) не содержат кириллицы — проверено по сабсетам Google Fonts: latin,
latin-ext, vietnamese. Русский текст в них подставлялся системным шрифтом
посетителя, разным на Windows, macOS и Android. В одной строке получались два
разных шрифта: «B2B» фирменным, «-системы, которые забирают…» системным.

**Как выбирали.** Скачали файлы девяти гарнитур и отрисовали образцы с
настоящими строками сайта в реальных кеглях на фирменном фоне, затем замерили
ширины набора — чтобы решение опиралось на цифры, а не на впечатление.

| Шрифт | Ширина латиницы к текущему | Вывод |
|---|---|---|
| Unbounded | **+29,8%** | отклонён: разъезжается вёрстка, характер рекламный |
| Onest | −3,5% | **выбран** |
| Golos Text | −2,1% | подходит, но нейтральнее по характеру |
| Wix Madefor Display | −4,2% | подходит, но ближе к обычному UI-шрифту |
| Martian Mono | **+14,3%** | отклонён: подписи не влезают в контейнеры |
| JetBrains Mono | 0,0% | **выбран** |
| IBM Plex Mono | 0,0% | равноценная альтернатива |

**Решение: Onest для заголовков, JetBrains Mono для подписей.** Onest —
геометричный гротеск с кириллицей и латиницей в одной гарнитуре, держит
отрицательный трекинг и почти не меняет ширину набора. JetBrains Mono —
инженерный характер, различимые `0/O` и `1/l` (важно для `CASE_001` и
`BUILD_2026.09`), ширина буква в букву как у DM Mono. Manrope в основном
тексте оставлен: кириллица у него есть.

**Что изменено.** В `:root` заведены `--font-display` и `--font-mono`, на них
переведены все 43 объявления гарнитуры (21 дисплейное, 22 моноширинных) —
раньше часть была задана шорткатом `font:`, из-за чего замена в одном месте
была невозможна. В `client/index.html` обновлены запрос к Google Fonts и оба
`preload`; ссылки теперь ведут на **кириллический** сабсет, а не латинский,
потому что сайт русскоязычный.

**Проверено.** Шрифты подменены локальными файлами через перехват запросов
(прокси песочницы Google Fonts не пускает), страницы отрисованы в браузере:
горизонтального переполнения нет ни на 1440, ни на 1280, ни на 390;
контраст не изменился (6/0/0). Мобильный кегль заголовка уменьшен с
`clamp(2.3rem, 9.4vw, 3.5rem)` до `clamp(2.1rem, 8.6vw, 3.3rem)`: Onest
чуть шире, и строка «часть продаж на себя.» переставала помещаться, оставляя
висячее «себя.» отдельной строкой.

## 5. Принятые решения и допущения

1. **Слой данных — типизированные `.ts`-модули** в `client/src/content/`
   (`types.ts`, `site.ts`, `services.ts`, `process.ts`, `trust.ts`, `team.ts`,
   `faq.ts`, `cases.ts`). Почему не CMS и не MDX: проект — чистый Vite SPA без
   content collections, а типы дают проверку на этапе `pnpm check` и
   используются сборкой для генерации sitemap.
2. **Кейс без доказательства не публикуется.** Поле `status: "draft"` держит
   такой проект вне главной и вне индексации — это защищает правило ТЗ «не
   выдумывать метрики» от постепенного размывания.
3. **Блок «Говорят цифры» заменён блоком кейсов.** Проверено: он выводил три
   вымышленных проекта (NORTH / KADO / SFERA) с придуманными метриками
   (+38%, −24%, 2.7×) — это прямо задокументировано в `design/README.md` как
   placeholder. Метрики удалены, карточка кейса получила поле `proof`
   (факт использования / финансирование / платящие пользователи).
4. **Единый CTA — «Разобрать задачу»** на всех экранах; «Смотреть кейсы» ведёт
   якорем на блок кейсов. Все CTA ведут в один сценарий — секцию `#contact`.
5. **Порядок секций** приведён к схеме ТЗ (01 Hero → 02 Проблемы → 03 Услуги →
   04 Кейсы → 05 Процесс → 06 Доверие → 07 Команда → 08 FAQ → 09 CTA).
   Чередование тёмных и светлых секций сохранено: светлыми остались
   «Как работаем» и «Команда».
6. **Форма отправляется в serverless-функцию** `api/lead.ts` (Vercel). Это
   единственный способ сделать серверную валидацию и rate-limit на статике.
   Антиспам без CAPTCHA: honeypot + проверка времени заполнения + лимит
   3 отправки/минуту на IP.
7. **`vercel.json` добавлен**: SPA-rewrite (иначе прямой заход на `/cases`
   отдавал бы 404), output `dist/public` и кэш-заголовки.
8. **Sitemap и robots генерируются на сборке** плагином в `vite.config.ts`,
   который импортирует `publishedCases`. Так список URL не может разойтись с
   реальным набором кейсов.
9. **Субагенты не запускались.** По правилу ТЗ («если блоки физически лежат в
   одном файле — выполняй последовательно сам») весь контент до этапа 2 лежал
   в одном `Home.tsx`, а после разбора работа свелась к переносу уже готовых
   текстов из ТЗ. Параллельный запуск дал бы конфликты по общим файлам
   (`index.css`, `SiteShell.tsx`, слой данных) без выигрыша.
11. **Аналитика на старте не подключается** (решение клиента от 17.09.2026).
    Причины: при десятках визитов в месяц агрегированные цифры не дают
    материала для решений, а Umami — self-hosted сервис, которому нужны
    сервер и база: для команды из четырёх человек это несоразмерные расходы
    на обслуживание ради счётчика.
    Что важно: **атрибуция от этого не страдает**. UTM-метки и referer едут
    вместе с самой заявкой (`lib/leads.ts` → `api/lead.ts`) и попадают в
    Telegram блоком «Источник». То есть вопрос «откуда пришёл этот лид»
    закрыт без аналитики; открытым остаётся только «сколько пришло и не
    написали».
    Что осталось в коде: слой событий (`track`, `initScrollDepthTracking`)
    и сами вызовы в компонентах. Он не требует переменных окружения и
    молчит, пока на странице нет провайдера. Загрузчик Umami, читавший
    `VITE_ANALYTICS_*`, удалён вместе с этими переменными.
    Как включить позже: добавить на страницу сниппет провайдера. Для Umami,
    GA4 (`gtag`) или Яндекс.Метрики (`ym`) правок в коде не нужно вообще —
    события начнут уходить сами. Для провайдера с другим API (например
    Vercel Web Analytics) — одна ветка в `track()`.

## 6. Известные проблемы / риски

1. ~~**Фотографии команды отсутствуют в репозитории.**~~ **Закрыто:** все
   четыре на месте в `client/public/team/`. Исходная причина — портреты
   грузились через dev-прокси `/manus-storage`, которого нет в продакшене.
2. **Заявки не доставляются в бот** — переменные заданы, но сообщения не
   приходят; причина не установлена, см. §4.4. Это блокирует единственный
   рабочий сценарий заявки.
3. **`/api/lead` нельзя проверить локально** через `pnpm dev` — Vite не
   поднимает serverless-функции. Проверено сценарно (мок ответов 200/503):
   success-state и fallback работают. Полная проверка — после деплоя.
4. **SPA без SSR.** Мета-теги проставляются на клиенте. Google это читает,
   но часть краулеров и части соцсетей — нет. В `index.html` лежат
   статические title/description/OG для главной, поэтому при шаринге главной
   всё корректно; для шаринга отдельного кейса потребуется пререндер.
   Полноценное решение — SSG/пререндер, это отдельная задача.
5. ~~**Express `server/index.ts` остался в репозитории**~~ — **закрыто**:
   удалён вместе со сломанным скриптом `start`, см. решение №13.
6. **Шрифты Google в песочнице не грузились** (перехват TLS), поэтому
   скриншоты сняты с фолбэк-шрифтом. Фолбэк шире Space Grotesk, так что
   отсутствие переполнений на скриншотах — оценка «сверху»; в продакшене
   типографика будет плотнее.

### Блокирует запуск

2. **Кейс «Архитектон» описан вслепую.** Домен `figma.com` закрыт сетевой

   окружения. После этого карточка переписывается по факту: заголовок,

5. Обложки кейсов: сейчас генеративная графика вместо реальных экранов
